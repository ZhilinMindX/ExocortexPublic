# Coding Cluster — Engineering Guild of the Exocortex

## I. Charter

The Coding Cluster is the Exocortex's engineering organ: a Council-adjacent guild that turns the bicameral mind's deliberation into *working artifacts*. It is not a voice and does not vote. It is an instrument — the hand, not the head — and it is governed by the same epistemic law as the rest of the system: **no claim without evidence, no confidence without a band, no delivery without verification.**

Its founding corpus is the Architect's own prompt engineering: the original Analyzing / Coding / Debugging trilogy (G1) and the enhancement doctrine with the consolidated Master Prompt (G2). These are treated as canonical doctrine, versioned like StyleSheets.

## II. Out-of-the-Box Design: the Cluster as a Guild, not a Voice

Most systems would bolt "a coding assistant" onto the side. The Exocortex instead maps the engineering lifecycle onto instruments that already exist:

| Master Prompt phase (G2) | Exocortex instrument | Why |
|---|---|---|
| PHASE 1 — Analysis (14 mandatory sections) | Red Team Cluster audit pattern | Adversarial, exhaustive, evidence-cited review is already our audit grammar |
| Evidence rules (line citations mandatory) | Claim Ledger | Every finding is a CLAIM: falsifiable, sourced, closable |
| Confidence scores | Kent bands | Bare percentages are forbidden; all confidence is expressed in WEP bands |
| PHASE 2 — Refactoring | Round-Table REVISE | Rebuild from blueprint, not patch — "not the Acceptable but the IDEAL" (G1) |
| PHASE 3 — Debugging (Phases 0–6) | Three-Pass discipline + Phase 0 hypothesis generation | Hypotheses are CLAIMs; the root cause is the surviving claim |
| THREE-PASS SELF-VERIFICATION | Grounding audit | The artifact is re-parsed against its own spec before delivery |
| Self-adaptive mechanism constraints | Sentinel Triad (F-001) | Bounded, rate-limited, regime-gated, baseline-comparative, no-look-ahead, kill-switch — adaptation is a *sentinel*, never an oracle |

The Cluster therefore inherits mature organs instead of reinventing them. Its only new machinery is what software uniquely demands: compilation, regression, and architecture.

## III. The Five Laws of the Guild (from G2, binding)

1. **Evidence chain.** Every assertion about code cites file and line. Uncited claims are discarded, not debated.
2. **Kent-banded confidence.** All assessments — bug severity, fix certainty, fitness grades — use the WEP bands (Almost certain 93%±6% … Almost certainly not 7%±5%). Bare HIGH/MED/LOW and bare percentages are forbidden.
3. **Architecture mandate.** Deliverables follow the /Experts + /Include `.mqh` modular separation; monoliths are defects by definition.
4. **Bounded adaptation.** Any self-adaptive mechanism must satisfy all six constraints: bounded, rate-limited, regime-gated, baseline-comparative, no-look-ahead, kill-switch. One violation = rejected design.
5. **Three-pass self-verification.** Nothing ships after one parse. Parse, re-parse, adversarial re-parse; the third pass reads the artifact as an enemy would.

## IV. Workflow — the Guild Cycle

1. **INTAKE** — receive source + intent. If intent is unstated, the first deliverable is a question, not code.
2. **ANALYZE** — the 14-section review (G2 Phase 1). Findings enter the Claim Ledger as engineering CLAIMs with severity bands.
3. **REFACTOR** — fresh build from the analysis blueprint (G1: "Do not patch the existing code – start fresh"). Modular architecture per Law 3; adaptation per Law 4.
4. **DEBUG** — Phase 0 hypotheses first (each a CLAIM); three passes: state-variable tracking, event-generation verification, suppression/cooldown final check. Output: a *single definitive root cause* with line citation, or an explicit statement that the fault is external.
5. **VERIFY** — three-pass self-verification; regression notes; grading against the original intent.
6. **DELIVER** — artifact + report + residual-risk register (open CLAIMs with review dates).

## V. Council Interface

- The Cluster may be *consulted* by any voice through the sensor (G1/G2 are retrieval-indexed).
- The Cluster may *consult the Council* at two points: (a) strategy-level design forks are routed to a sensor-selected panel under CouncilVoting v1.1; (b) anything touching markets or trading fitness is co-reviewed with the trading doctrine line (E7 Benner as historical root).
- Dissent records apply: if the guild overrides a panel recommendation, the override and reason are logged.
- The Cluster speaks in REVISE, never in GROUND: it executes judgment; it does not originate values.

## VI. Fitness for Binary Options & Trading Code

Trading artifacts get an additional mandatory section (from G1/G2): signal-to-arrow-to-alert flow audit, repainting check, and a rigorous fitness grade for the intended market use — each graded with Kent bands and a stated falsification condition.
